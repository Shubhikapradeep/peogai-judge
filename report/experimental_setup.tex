\section{Experimental Setup}
\textbf{Hardware.} All batch experiments ran on Google Colab with a single NVIDIA Tesla T4 (16\,GB) GPU in one session. The live demo runs Qwen2.5-Coder-3B-Instruct locally on an Apple MacBook Pro (M3 Pro) through Ollama, with no GPU server.

\textbf{Models and inference.} Both judges come from the same family, so that scale is the only variable: Qwen2.5-Coder-3B-Instruct in fp16 and Qwen2.5-Coder-7B-Instruct in 4-bit (the official AWQ checkpoint). Inference used vLLM. Inputs use each model's chat template with a fixed system message. The context window is set to 12{,}288 tokens; the longest pair is about 7k tokens, so no input is truncated.

\textbf{Decoding and parsing.} Experiments 1, 2, 3 and 4b use greedy decoding. Experiment 4c samples three completions at temperature 0.7 (top-$p$ 0.95, seed 42) and takes the majority; a tie counts as no verdict. Output is limited to 16 new tokens, since every prompt asks for a single token. A rule-based parser maps each output to a verdict; outputs it cannot map count as parse failures (none occurred in any run).

\textbf{Scale and cost.} Table~\ref{tab:runs} lists every run. In total we made 2{,}400 judge calls (3{,}000 generations including the three samples per call in Exp.~4c) in 1.27 GPU-hours. Mean latency per call was 1.6\,s for the 3B judge and 2.5\,s for the 7B judge. The runner saves results to persistent storage every 10 calls and resumes after interruptions, so a run spread over several Colab sessions still covers each item exactly once.
